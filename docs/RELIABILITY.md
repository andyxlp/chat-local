# Connectivity, uptime and recovery

## Baseline defect and unknowns
Upstream server.js reports dashboard status online unconditionally while process is alive; its Cloudflare exit handler only sets tunnel error if publicUrl has not yet been assigned. A dead tunnel can therefore leave a stale URL/green badge. This is consistent with the owner's repeated 2–3h ChatGPT failures, not proof of root cause. Also investigate OAuth refresh, session handling, client idle expiry, macOS sleep/network, proxy timeout, tunnel process state and provider-side errors.

Cloudflare official documentation identifies Quick Tunnels as development/test, no uptime guarantee, changing URL, and no SSE support. Do not use quick tunnels for normal operation. Tailscale Funnel is public, currently documented beta, requires compatible macOS CLI variant/HTTPS/MagicDNS and has bandwidth constraints; its relay does not decrypt content. Named Cloudflare Tunnel is alternative with stable user-managed hostname, provider edge TLS termination, account/domain setup. Verify actual conditions and compatibility before recommending either.

## R requirements
R01 stable canonical URL per installation, independent fixed remote port; only owner explicitly changes provider/hostname. Never silently create new URL or require connector recreation for recoverable outages.
R02 separately track daemon readiness, tunnel ownership/process status, public HTTPS reachability, last authenticated MCP request per client, auth token/refresh failure counters and actual client probe outcome. Never infer remote success from daemon uptime.
R03 public minimal health endpoint (no file paths, tool names, clients or version) and authenticated synthetic probe where possible. Probe from local network via public origin and, in tests, independent external vantage; local probe alone not evidence of provider accessibility.
R04 state: Off, Starting, Local ready, Connecting, Reachable (not yet client verified), Connected (recent actual call), Degraded, Paused, Stopping. Include timestamps, cause, action. Stale health must turn unknown/degraded; no perpetual green.
R05 supervisor detects owned child exit, stale health, network interface change/wake; bounded retry with exponential backoff+jitter (1,2,4,8,16,30,60s cap), circuit breaker after repeated failures, visible manual retry. Prevent parallel duplicate tunnel processes; generation ID avoids stale callbacks. Do not restart on auth errors; guide reauthorization. Preserve stable hostname and credentials. Never kill unrelated processes.
R06 stop/pause: deny new tool calls immediately, close or gate remote listener, cancel tracked jobs, shut down only owned route/process, check removal and report failure. Resume explicitly. No unexpected remote exposure after crash/reboot. Keep existing valid grants only if user chooses, default pause retains grants but disables them globally.
R07 auth durability: atomic store, token expiry/refresh rotation/replay detection, survive restarts with valid grants, correct time handling, test concurrent refresh and lost responses. Fail closed on corrupted state; offer safe reset/reauthorization.
R08 bounded sessions/jobs/cache; protocol-appropriate keepalive, cleanup expired records, backpressure, timeouts, request cancellation and retry safety. Do not replay writes or commands after timeout; use operation IDs/idempotency where possible, show outcome unknown if not confirmed.
R09 macOS sleep/offline: no access guarantee; wake/reconnect recovery; never alter system sleep preferences automatically. User may explicitly choose awake while active (if implemented, visible opt-in with battery warning).
R10 diagnostics local only, redacted. Capture reason categories: local stopped, port in use, tunnel missing, provider sign-in needed, DNS/TLS, public blocked, OAuth invalid/expired/revoked, protocol mismatch, timeout, client-side unknown. Distinguish actions repair tunnel vs reauthorize vs refresh client. No raw token/URL secret.
R11 time budget targets: health probe every 30s while active (configurable, no polling when off), timeout 5s; mark degraded within 60s of failure; recover within 120s after connectivity restored in controlled scenarios, excluding DNS provisioning/provider outage and Mac sleep. Document measured p50/p95 and exceptions. No guarantee of uninterrupted internet service.
R12 8h and 24h soak on actual macOS with 3h idle intervals, refresh crossings, sleep/wake, Wi-Fi change, tunnel child exit and daemon restart. Test actual existing connectors before/after. Measure core/app/tunnel separately, no unbounded RSS growth or jobs/session leaks.

## Provider adapter contract
configure -> start -> status -> stop -> reconcile. Validate official version and installer, check port ownership, record provider-owned resource ID/config and canonical origin, compare expected vs observed, do not modify other Tailscale/Cloudflare resources. Prefer foreground owned process where possible; for persistent Funnel disable only owned listener, confirm status. If cannot ensure exclusive ownership, require operator setup and no destructive reset. Named Cloudflare credentials in secure store, never shell env/logs; don't create external account/domain without owner. Quick tunnel debug-only explicitly marked ephemeral and not accepted as P04. No autonomous provider failover or changing DNS.

## Tests
Use deterministic fake tunnel/clock for fault injection; actual tunnel for end-to-end. Check existing connector can resume after deliberate pause, restart and transport disconnect without changing URL (valid tokens permitting). Test auth refresh while idle and concurrent calls, ensure a 401 is not labeled tunnel error, and tunnel failure is not labeled auth failure. Include failed/blocked outcomes and exact evidence in delivery status.
